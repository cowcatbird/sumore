# Architecture

Sumore separates the shared circle state from device-local app restrictions. Supabase authorizes account and circle operations; the native module applies restrictions using each operating system's APIs.

## Mobile app

`apps/mobile/src/app` contains Expo Router screens. Shared components live in `src/components`, with the theme in `src/constants/theme.tsx`. Pure rules and parsers live in `src/domain`; service wrappers in `src/services` handle the backend, notifications, account access, and feedback.

`src/features/app-store.tsx` coordinates connected app state. `src/features/local-art-preview.tsx` supplies isolated sample data for development. The preview provider is gated by development mode and an explicit environment flag.

## Native Screen Time

`apps/mobile/modules/screen-time` exposes an Expo module backed by Swift on iOS and Kotlin on Android. Config plugins in `apps/mobile/plugins` generate platform capabilities and extension targets.

iOS stores opaque Family Controls selections in the shared App Group. Device Activity monitoring and Managed Settings apply restrictions. Android keeps selected packages, allocations, and usage state on the device, with Usage Access and Accessibility supporting enforcement. Platform authorization is distinct from enabling a daily limit or actually reaching it.

Approved extra time comes from a server-issued grant with an account identity and fixed deadline. The controller validates the response before passing it to native code. Retries must not restart the countdown. Account switching clears or replaces account-bound native state.

See the [native module guide](../apps/mobile/modules/screen-time/README.md) for the bridge and platform limitations.

## Shared backend

`supabase/migrations` defines profiles, circle membership, time requests, approved grants, shared wallets and purchases, recovery-key metadata, and moderation records. The app uses authenticated RPCs and row-level security rather than trusting caller-supplied account IDs.

Three Edge Functions serve distinct purposes:

- `account-access` verifies authenticated callers for recovery-key operations and account deletion.
- `push-notifications` accepts authenticated database webhooks and sends notifications through Expo.
- `report-problem` is an optional email-delivery endpoint. The current mobile feedback flow opens a user-reviewed email draft instead.

## Account and privacy boundaries

New installations can sign in anonymously. Public friend codes are generated by the server and cannot be edited. Private login keys restore an existing account; they are separate from friend codes. The server stores recovery-key hashes, while device copies use secure storage where available.

Selected app tokens, package selections, and usage measurements remain on the device. Users may explicitly share text labels and allocations with their circle. Shared names, request text, moderation evidence, and account data belong to the backend's access-control and retention rules.

The support website is static HTML and CSS. Its deletion page provides instructions and a user-reviewed email request; it does not delete accounts automatically. In-app account deletion uses the authenticated backend flow.
